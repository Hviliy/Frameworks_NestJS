# Workshop Booking System

Система управления бронированием мастер-классов на NestJS.

## Технологии

- Node.js и TypeScript;
- NestJS;
- TypeORM;
- SQLite;
- Docker;
- Postman.

## Запуск через Docker

Создайте `.env` на основе `.env.example`, затем выполните:

```
docker compose up --build
```

Базовый адрес API: `http://localhost:3000/api`.

## Локальный запуск

```
npm install
npm run migration:run
npm run start:dev
```

## Создание администратора

Укажите `ADMIN_USERNAME`, `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`.

Для локального приложения:

```
npm run admin:create
```

Для приложения в Docker:

```
docker compose exec api npm run admin:create
```

Команда создаёт администратора или обновляет существующего пользователя.

## API

### Аутентификация

- `POST /api/auth/register` — регистрация пользователя;
- `POST /api/auth/login` — вход и получение JWT;
- `GET /api/auth/me` — получение текущего пользователя.

### Мастер-классы

- `GET /api/workshops` — публичный список;
- `GET /api/workshops/{id}` — публичные детали;
- `POST /api/workshops` — создание администратором;
- `PUT/PATCH /api/workshops/{id}` — обновление администратором;
- `DELETE /api/workshops/{id}` — удаление администратором.

### Бронирования

- `GET /api/bookings` — свои бронирования, для администратора — все;
- `GET /api/bookings/{id}` — просмотр доступного бронирования;
- `POST /api/bookings` — создание бронирования;
- `PUT/PATCH /api/bookings/{id}` — изменение бронирования;
- `DELETE /api/bookings/{id}` — отмена бронирования.

Для защищённых запросов передавайте JWT:

```
Authorization: Bearer <access_token>
```

Система запрещает бронирование прошедших мастер-классов, повторное бронирование
одним пользователем и бронирование сверх вместимости. Обычный пользователь
видит и изменяет только свои бронирования.

## Проверка через Postman

Коллекция находится в
`postman/workshop-booking-system.postman_collection.json`.

1. Запустите приложение и создайте администратора.
2. Импортируйте коллекцию в Postman.
3. Откройте переменные коллекции и проверьте `base_url`, `admin_username` и
   `admin_password`. Значения администратора должны совпадать с `.env`.
4. Нажмите **Run** и запускайте запросы строго в исходном порядке.

Коллекция автоматически:

- создаёт двух пользователей с уникальными именами;
- получает и сохраняет JWT;
- проверяет публичные и защищённые маршруты;
- проверяет права пользователя и администратора;
- проверяет CRUD мастер-классов и бронирований;
- проверяет запрет дублей, превышения вместимости и доступа к чужой брони;
- удаляет созданные бронь и мастер-класс.

Если выполнение прервалось до раздела очистки, созданный мастер-класс можно
удалить вручную запросом `DELETE /api/workshops/{id}` от администратора.

## Структура

- `src/auth` — регистрация, вход и JWT-аутентификация;
- `src/users` — пользователи и роли;
- `src/workshops` — мастер-классы;
- `src/bookings` — бронирования;
- `src/common` — общие guards, декораторы, фильтры и валидаторы;
- `src/database` — конфигурация TypeORM и миграции;
- `postman` — автоматическая коллекция Postman.
